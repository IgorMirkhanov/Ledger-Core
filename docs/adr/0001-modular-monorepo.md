# ADR-0001: Монорепозиторий, один go.mod, database-per-service

**Статус:** принято

## Контекст
Проект состоит из 5 процессов. Нужно показать микросервисную архитектуру,
но без операционной сложности multi-repo для одного разработчика.

## Решение
- Один репозиторий, один `go.mod`, отдельный `cmd/<service>` на каждый процесс.
- Сервисы не импортируют `internal/<другой сервис>`; общаются только через gRPC/Kafka-контракты.
  Правило проверяется ревью (и может проверяться `depguard`).
- Каждый сервис владеет своей БД. В docker-compose это один инстанс Postgres с тремя базами.

## Последствия
+ Атомарные изменения контракта и реализации, единый CI.
+ Легко выделить сервис в отдельный репозиторий: границы уже есть.
− Нужно следить, чтобы общий `internal/platform` не превратился в «общую бизнес-логику».
