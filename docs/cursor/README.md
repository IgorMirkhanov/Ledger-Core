# Как работать с Cursor над Ledger Core

Разделение ролей: **архитектура, схема БД, контракты и инварианты уже спроектированы** (docs/, api/proto, migrations,
domain-слой). Cursor реализует механику по пошаговым промптам.

## Подготовка (один раз)

1. Открой репозиторий в Cursor. Правила из `.cursor/rules/` подхватятся автоматически
   (`00-project` всегда, остальные по glob'ам файлов).
2. Settings → Models: для промптов 04–07 (деньги, конкурентность) используй самую сильную модель.
3. Проверь окружение: `make tools && make build && make test` (Go 1.26, Docker).

## Цикл работы над одним промптом

```
1. Новый чат (Agent mode). Не продолжай старый: контекст должен быть чистым.
2. Скопируй содержимое docs/cursor/prompts/NN-*.md целиком, включая строку «Контекст» с @-ссылками.
3. Сначала попроси план:  «Сначала покажи план изменений по файлам, код не пиши».
   Сверь план с docs/. Если Cursor предлагает менять схему, proto или домен, откажи.
4. «Реализуй план». Большие промпты (05, 06, 08) делай по частям A/B/C: каждая часть в отдельном сообщении.
5. Проверка (руками, не доверяй «всё работает»):
     go build ./... && go vet ./... && make lint && make test && make test-integration
6. Ревью диффа по чек-листу ниже.
7. Коммит (сообщение из промпта) → push → CI зелёный → следующий промпт.
```

## Чек-лист ревью (особенно для 04–07)

- [ ] Нет `float` рядом с деньгами.
- [ ] Балансы меняются только через `JournalEntry.Apply` на заблокированных счетах; `InsertEntry` отклоняет неприменённую запись.
- [ ] Idempotency Begin/Complete + outbox.Add в ОДНОЙ транзакции с бизнес-изменениями.
- [ ] LockAccounts перед чтением балансов для принятия решения, порядок по id.
- [ ] Нет сетевых вызовов внутри открытой транзакции БД.
- [ ] Ошибки обёрнуты с контекстом, доменные ошибки — sentinel'ы, наружу не утекают детали.
- [ ] Каждая горутина останавливается по ctx.
- [ ] Тесты проверяют инварианты (сумма денег сохраняется), а не только «нет ошибки».
- [ ] Не изменены существующие миграции, proto (без запроса), тесты не ослаблены.

## Порядок промптов и зависимости

| # | Промпт | Зависит от | Результат |
|---|--------|-----------|-----------|
| 01 | testing-foundation | — | testcontainers, тесты схемы/idempotency/outbox |
| 02 | kafka-consumer | 01 | consumer + DLQ |
| 02a | consumer-rebalance | 02 | исправление по ревью: rebalance, shutdown |
| 03 | observability | — | трейсинг, метрики, дашборд |
| 04 | accounts-repository | 01 | pgx repository |
| 05 | accounts-service-grpc | 04 | **рабочий ledger** + тест конкурентности |
| 06 | transfers-saga | 05 | saga + recovery |
| 07 | transfers-grpc-e2e | 06 | e2e переводы |
| 07a | freeze-semantics | 07 | исправление по ревью: одно правило заморозки (ADR-0009) |
| 07b | worker-resilience-lease | 07a | исправление по ревью: воркеры не роняют процесс, аренда шагов |
| 08 | gateway | 05, 07 | публичный REST, `make up` + demo |
| 09 | notifications | 02, 05 | уведомления |
| 10 | reconciler | 05 | сверка |
| 11 | load-testing | 08 | цифры для README |
| 12 | chaos-and-polish | всё | финал |

03 можно делать в любой момент после 01; удобнее сразу после 05.

## Если Cursor застрял или спорит с архитектурой

Скопируй его вопрос/предложение и принеси в чат с Claude («мозг»). Решение фиксируется
новым ADR в `docs/adr/` и правкой документации, только потом меняется код.
